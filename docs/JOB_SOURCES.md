# 在线岗位来源、投递记录与每日推荐

## 当前能力

在「求职雷达 → 来源与导入」保存文档名称、类型和链接，可直接打开原始文档。链接只存入本机 SQLite，不写进源代码。

- **岗位信息库**：用于求职页每日岗位推荐。
- **投递记录**：导入个人已有申请，保留日期、流程阶段、备注，进入求职表格和看板。

当前接入为**导出文件快照导入**，没有后台爬虫或在线自动同步。求职页按照本地日期与偏好重新计算推荐，来源卡片显示上次实际导入时间；保存一个链接并不等于已读取其内容。

## 导入腾讯文档 / 飞书导出文件

1. 在原文档中使用导出/下载功能，保存目标表为 `.xlsx` 或 `.csv`；也支持 `.tsv`，旧 `.xls` 需另存为 `.xlsx`。
2. 在来源卡片点击「导入此来源」，选择文件、对应工作表和表头。
3. 检查字段映射。公司与岗位名称必选；其他列可选择不映射。无法匹配的字段保存在备注的「导入原始字段」中，JD 保存到专用正文而不重复塞进备注。
4. 选择没有阶段时的默认值。信息库默认「收藏/待评估」，投递记录默认「已投递」。未知阶段会列为错误，不猜测进度；例如「一面/二面/HR面」保留对应轮次，「终面」保留为轮次待确认的旧面试阶段，并在原始字段中保留具体名称。
5. 点击预览，核对新增、更新、重复与错误数量。预览不会写入岗位。
6. 确认后仅导入有效新增/更新行。重复及错误行跳过；有错误时先修正原表再导入。没有有效行会明确拒绝，不伪装为成功。

每次最多 10 MB、2000 条数据、100 列；预览列表显示前 100 行，汇总和导入覆盖全部行。文件仅传到你本机应用处理，不发给腾讯/飞书之外的服务，也不传给 AI。基础功能运行时不会请求原文档。

CSV 支持 UTF-8、GB18030 和带 BOM 的 UTF-16，处理中文、逗号、引号、换行。Excel 支持多工作表、标准日期和链接；不执行公式或外部连接，只读取已有单元格值/缓存结果。

日期应包含年份（如 `2026-10-11`、`2026/10/11`、`2026年10月11日`）。缺少年份的 `10月11日` 不会擅自补年份。校招资格只接受符合、不符合、待确认（或是/否）；来自表格的资格标记仍需你核实。

校招模板中的「投递志愿与顺序」可自动识别为岗位，「base」识别为地区。「投递」归入已投递、「测评」归入笔试、「简历挂」归入未通过，具体原始状态保留在备注。「对应日期」不自动当作投递日期，应先确认其含义。只有网页标题而没有真实 URL 的链接列应选择不映射，标题仍保留在原始字段中。JD 图片文件名不等于图片正文，导入文件名不会自动获得图片内容。

通用导入每次处理一个工作表，不会自动把进度附表关联到主表。历史进度可另行整理为流程日志；仅有日期时应在备注保留日期，不编造面试时间。公司或岗位缺失时预览会报错，先补充原表后再导入。

## 重复与更新

按规范化的公司、岗位名称与地区检查；空地区按未指定处理，同公司同岗位可能判为重复。不同地区均有明确值时视为不同岗位。预览会显示结果。

默认跳过重复，不覆盖现有信息。勾选「允许更新」后：

- 可更新同一个来源已导入的岗位；仅更新非空且已映射的字段，空字段不会擦除已有值。
- 可将信息库候选转为个人投递记录，保留岗位 ID 和已有任务关联。
- 不会用信息库覆写个人投递记录，也不会覆盖已有手动记录。
- 更新阶段时自动追加日志，未映射的字段及人工补充保留。新导入的投递记录追加导入日志。

删除来源入口后岗位仍保留，解除来源链接，不会删除申请记录。

## 每日推荐规则

只使用来源类型为信息库、阶段为收藏/待评估且未归档的实际岗位。排除已过截止日期、明确不符合校招资格，以及在投递历史中已出现的同一岗位。

按关键词命中（默认内容、品牌、营销、AI、出海）、地区偏好、7 天内截止、资格标记排序，最后按截止日期与稳定 ID 打破并列。推荐数量可设为 1–20。规则分只用于排序，不显示为 AI 或简历匹配分数。每天按本机日期重新评估，不保证每天都有全新岗位。

「加入待投递」后移出推荐并进入待投递看板。无数据时显示空状态，不虚构职位。快照中的链接、截止时间和在招状态须以官方岗位为准。

## 迁移、备份与隐私

数据库新增第 2 号迁移建立 sources 表，保留已有记录。旧库的岗位来源默认手动；旧 JSON 备份仍可读取，缺失来源和推荐偏好时采用兼容默认值。新备份包含来源链接、导入岗位和推荐偏好，可能包含私人信息，应存放到仓库外。

**当前云端保存的来源和数据不会随 GitHub 克隆自动进入 Windows。** 在设置中导出 JSON，在 Windows 上导入即可迁移。数据库、表格导出、私人 JSON/CSV 和文档链接备份不要加入 Git；提供的链接未硬编码进公开源代码。

如需要未来在线同步，应使用服务商支持的接口及授权，确认共享权限、访问范围和凭据后再开发。不要把浏览器 cookie 或登录密码发到聊天或源代码中。
