# 阶段 A 技术决策

1. **Next.js App Router + React + TypeScript + Tailwind CSS**：同一项目包含页面和 Node API。运行命令固定绑定 127.0.0.1。使用当前兼容版本，并提交 package-lock.json 保证复现。
2. **Node.js 24 内置 SQLite**：采用 `node:sqlite` DatabaseSync 而非 better-sqlite3，避免 Windows 原生扩展编译及额外工具链。明确要求 Node 24；用参数化 SQL 代替 ORM，Zod 验证所有写入。同步访问适合单用户本机工作负载，数据库不可供网络多人共享。
3. **数据库结构**：jobs、tasks、job_events、app_settings 四表。独立主键与真实外键维护岗位关联；结构化 JSON payload 保留类型化业务字段。删除岗位清除事件、解除任务外键；读任务时以实际外键为准。每次记录更新写 updatedAt；任务完成记录 completedAt。SQL 表迁移以 user_version 管理，在事务中执行。阶段 B/C 再追加实体表，不预置无法操作的空壳功能。
4. **组件**：使用轻量自建组件与 Lucide 图标，避免初始项目引入不需要的 UI 库。保留焦点可见状态、标签、对话框焦点限制和键盘排序替代拖动。无远程字体、图像或 CDN，运行时可离线。
5. **规则排程**：未完成、未归档任务候选；面试优先仅针对 48 小时内相关任务，之后按 P0/P1/P2 与截止日、创建时间排序。在面试优先模式下先预留一项能放入预算的论文任务。全任务能放入剩余预算才选入，不拆分或虚构完成记录。手动顺序仅当天有效，下个自然日恢复规则。余量不足时明确提醒。
6. **统计边界**：实际专注分钟由用户填写，统计本周完成的任务；没有提供计时器，也不推断活跃时长。四模块进度仅是公共任务完成率。论文节点目前为有截止日的论文公共任务。
7. **备份**：阶段 A 完整 JSON，带版本、结构验证与引用完整性验证，导入单事务合并。重复 ID 保留已有记录，空库恢复设置；不同 ID 同名记录不自动合并。CSV 防止 Excel 公式执行。此阶段无附件，无需 ZIP。
8. **安全与范围**：没有用户账户，不开放到局域网/公网。写入有 Origin/Host 校验，不执行 JD 或备注内的 HTML。JSON 限制 10 MB。API 密钥、录音、外部 AI 适配、论文与雅思专属数据模型在对应后续阶段实现。上传的 PRD 作为产品规格保留；验收按用户要求只覆盖阶段 A。
