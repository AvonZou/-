# 操作效率重构：第一阶段

范围依据：2026-10-12 用户提出的极简重构要求优先于旧 PRD 的首页展示和投递表单布局。本阶段只实现投递记录和首页，不引入收费 AI，不改变 React / TypeScript / Tailwind / Node.js 24 / SQLite 技术栈。

## 审查结论与分阶段计划

| 当前操作成本                                         | 改造                                                                                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 首页统计、推荐、预算、全量排程、节点和模块进度并列   | 第一阶段：首页只保留四行动、最多三项重要任务和提醒；提供全局快捷新增                                                        |
| 投递列表七列，新增十余字段，面试阶段笼统             | 第一阶段：四列、四字段快速新增/编辑，九流程行内修改                                                                         |
| 行内改流程提交整条岗位，可能覆盖较新的隐藏字段       | 第一阶段：独立局部更新接口，服务器读取当前记录后合并，保留资料和历史                                                        |
| 仓库没有招聘网页抓取或 JD 文本解析实现，只有文件导入 | 第二阶段：先验证真实 URL 的响应、页面类型与失败原因；再实现合法可访问页面和文本解析、缺失字段提示、预览保存及浏览器扩展接口 |
| 面试、论文、雅思只有预留页与公共任务入口             | 第三阶段：题目练习归档、研究下一步和最近文献、今日雅思练习与错题；统一交互                                                  |

第二、三阶段尚未实现。本阶段没有新增网页自动获取、AI 面试反馈、论文文献库或雅思错题库。

## 第一阶段行为

- 首页四个行动入口：「找岗位」进入求职推荐；其他三个进入对应模块预留页，已有公共任务创建仍可使用。
- 今日重点最多三项：未归档、未完成、到期或无日期的任务；面试优先模式可纳入未来 48 小时面试任务。优先级和截止日排序，保留当天手动排序；不受预算导致的大任务排除影响。
- 提醒包含逾期及未来七天任务截止、岗位截止、跟进和面试安排。已结束或归档记录不产生岗位提醒。默认显示六条，可展开全部。
- 投递表只有公司、岗位、投递日期、当前流程。流程选择、编辑、详情和删除操作放在当前流程单元格内，不添加资料列。
- 新投递默认使用浏览器所在设备的当天日期和「已投递」。只填写公司、岗位、日期、流程；快速编辑只更新这四项。
- 九流程可任意往返：已投递、初筛、笔试、一面、二面、HR面、Offer、未通过、主动放弃。切换成功后追加日志，失败保留旧值并显示错误。
- 旧「收藏/待评估」「待投递」「面试」「未通过/结束」保持有效。旧记录的选择器包含其原值和九个新流程，可由用户明确选择；不推断面试轮次或结束原因。
- JD、来源、详细资料与历史保留在详情；「编辑资料」进入原高级表单。推荐移到求职页；来源导入、看板、训练任务、归档、备份、任务排程及复盘仍保留。
- 搜索和流程筛选直接可用，公司、方向、日期、记录类型、归档折叠到更多筛选。主表导出全部记录的四列 CSV；完整 JSON 及原完整 CSV 接口继续保留。

## 数据兼容与备份方案

1. 开发前用 Node.js SQLite 在线备份 API 备份默认数据库，单独保留原始 payload 快照；私人备份与快照位于被 Git 忽略的 data 目录。
2. 数据库表结构及 `PRAGMA user_version=2` 不变，没有数据清空、表重建或批量阶段改写。扩展的是 TypeScript/Zod 枚举，旧 payload、ID、关联和日期保持原样；因此本阶段无需新增 SQL 迁移。
3. `POST /api/applications`、`PUT /api/applications/:id` 接收四字段，快速编辑从数据库读取完整当前记录并合并。
4. `PATCH /api/jobs/:id` 仅接受 stage；其他字段或无效状态被拒绝。持久化和日志沿用现有事务。
5. `npm run db:backup` 创建独立 SQLite 快照到 `data/backups`，含 WAL 已提交记录。新版 setup.bat 在依赖安装、初始化及构建前自动备份，失败中止安装。
6. 新版本读取旧 JSON 备份；新流程数据应使用新版本恢复，旧版应用不支持新流程枚举。回退需停止服务，保存当前数据，再使用匹配的代码和升级前备份，不直接替换仍打开的数据库。

## 验收

1. 打开首页，确认四入口、最多三项重点任务、提醒，以及右上角快捷新增。
2. 新增投递仅出现四字段，日期为当天；保存、搜索、刷新，记录仍在。
3. 在表格直接切换九流程，并从 Offer/主动放弃返回任意流程；详情中查看变更日志。
4. 对已有含 JD、链接和备注的岗位做四字段编辑，检查后台资料未被清空。
5. 验证搜索、流程筛选、四列 CSV 导出和删除；删除岗位后相关日志清理，关联任务解除关系并保留。
6. 停止并重启服务，检查 ID、日期、流程和日志仍在；进入来源导入、看板、任务排程与备份，检查原功能仍可用。

自动化验证使用临时库或 `.cache/e2e-data`，不向私人数据库写测试记录。测试结果见 TEST_RESULTS.md；Windows 实机仍需上述人工验收。

## 更新到 Windows 原路径

云端无法直接访问 `D:\Vibe Coding\NextStepOS`。先停止本地服务并导出 JSON，再备份整个 data 文件夹到项目外。

如果此目录是 Git 克隆，在 CMD 中执行：

```bat
cd /d "D:\Vibe Coding\NextStepOS"
git pull --ff-only origin main
setup.bat
start.bat
```

若 git pull 报有本地修改，先保留自己的改动，不使用强制重置。

如果此前下载的是 ZIP，重新从仓库 main 下载 ZIP，解压到临时目录，将包含 package.json 的目录中的代码覆盖到上述路径。保留原 data、backups 和 .env 文件；不复制个人数据库到 GitHub，也不使用空数据替换旧数据。然后双击 setup.bat 和 start.bat。

保留原 data 后无需再次导入个人 JSON；JSON 用于备份与另机迁移。安装 Node.js 24 LTS，初次安装依赖需联网。setup.bat/start.bat 的路径处理支持空格，本交付没有在用户 Windows 电脑运行脚本。
