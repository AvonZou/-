# NextStep OS Windows 启动说明

## 环境与安装

支持目标：Windows 10/11、Node.js **24 LTS**、当前 Chrome/Edge。此交付在 Linux 云环境完成自动化测试；Windows 脚本尚需你在真实 Windows 上验收。

从 nodejs.org 安装 Node.js 24 LTS（安装器包含 npm），重新打开终端后运行 `node --version`、`npm --version` 确认。将仓库放在有写权限的普通目录，例如 `C:\Projects\NextStepOS`，避免压缩包内直接运行。项目路径含空格也可以。

首次双击 `setup.bat`，等候依赖安装及生产构建。脚本会保留现有数据库，失败会暂停并显示错误。首次安装需要联网访问 npm；运行时不需要联网或密钥。

以后双击 `start.bat`，浏览器会在服务就绪后打开 `http://127.0.0.1:3000`。如浏览器没有自动打开，手动输入此地址。终端必须保持打开；停止请按 `Ctrl+C`（批处理提示是否终止时输入 Y）。不要修改监听地址为 `0.0.0.0`。

## 手动运行

在项目目录打开终端：

```powershell
npm ci
npm run db:init
npm run build
npm start
```

开发模式用 `npm run dev`，无需先构建。不要同时启动开发和生产服务。

## 数据初始化、备份和恢复

- `npm run db:init` 创建 `data/nextstep.db`、执行迁移、建立空表。可重复运行，不覆盖记录。
- 在「设置与备份」点击导出完整 JSON，选择保存位置。岗位可额外导出 CSV；CSV 不用于完整恢复。
- 恢复：选择导出的 JSON，检查预览数量，确认合并导入。相同 ID 跳过而不覆盖；不同 ID 的同名记录视为不同记录。导入不自动去重公司或任务标题。
- 向空数据库导入可恢复全部阶段 A 记录及排程设置。向已有数据导入会保留现有设置和同 ID 记录。
- 如需恢复到空库，先停止应用，备份当前 `data` 文件夹到仓库外，再将整个 `data` 文件夹移到安全位置，启动应用后导入 JSON。不要只删除 `.db` 而保留 WAL/SHM 文件。不会提供一键清空以避免误删。
- 完整文件备份：先停止服务，再复制整个 `data` 文件夹。未来录音/附件上线后应使用文件备份包含附件；当前版本尚无录音功能。
- 备份可能包含个人 JD、备注和求职信息，请放在仓库外，不要提交到 GitHub。

## 升级

先导出 JSON 并关闭服务，在项目目录更新代码，再运行 `setup.bat` 重新安装锁定依赖并构建，最后启动。迁移在事务中执行；不自动降级数据库。若数据库版本比代码新，应使用匹配的新版本应用。若需回退，使用对应旧代码与升级前的备份。

## 常见问题

- **找不到 node/npm**：安装 Node.js 24 LTS 并重新打开终端。
- **端口 3000 被占用**：先关闭原来的 NextStep OS 服务，或停止占用端口的其他服务后重试。不要结束不认识的进程。
- **依赖安装失败**：检查网络连接与 npm 错误，重跑 setup；不要关闭 TLS/签名验证。
- **权限不足/数据库无法写入**：把项目放到当前用户可写目录，不要放到 Program Files。
- **更新界面没有变化**：重新运行 setup 完成生产构建，然后重启。仅修改源码不会更新已有生产构建。

## 测试

`npm run typecheck`、`npm test`、`npm run build`。浏览器自动化需要 `npx playwright install chromium`，之后停止应用并运行 `npm run test:e2e`。测试库使用 `.cache/e2e-data`，不接触默认私人数据。完整手动流程见 TEST_PLAN.md。
